## 概要

モデルカタログ(10,000+ モデル。foundry-models-overview 2026-07-28 版は「over 10,000 models、月約 50 モデル追加」。初版の 1,900+ は旧記載)、モデルファミリ別の提供状況、デプロイタイプ、Model router、モデルライフサイクル、ファインチューニング、Foundry Local を扱う。カタログは「**Models sold by Azure(Azure Direct)**」(Microsoft がホスト・販売、MS サポート・SLA・Responsible AI 審査付き)と「**Models from partners and community**」(第三者提供、Azure Marketplace 課金)の2区分で整理される。

## 補足ノート(SI 判断に効く要点)

- **⚠ Fireworks 系モデルは予告期間が 15 日しかない**: リタイアスケジュールに Important として「**Fireworks models on Standard (Per-Token) inference offerings are subject to a 15-day notice period prior to model retirement**」と明記。標準ライフサイクル(GA は 60 日前通知)と比べて極端に短く、`FW-*` 系(GLM / Kimi / Qwen / MiniMax / DeepSeek の Fireworks 版)を本番の必須経路に置くとガバナンス上のリスクになる。掲載上のリタイア日は 2027-07-01(2026-09-21 版でも同じ)だが、この予告条項が優先する。2026-07-28 GA の `FW-Kimi-K3` は schedule の Fireworks 表にまだ載っていない。
- **日本語モデル**: **NTT Data の `tsuzumi-7b` は 2026-08-31 に期限到来(後継 `tsuzumi2`)**。retirement schedule 2026-09-21 版でも Legacy 表記のまま、models-from-partners 2026-09-21 版にも掲載継続(hub-based プロジェクト必須)で「retired」の明示は未確認。日本語特化モデルを検討する案件では後継への切替を前提にする。
- **Claude の位置づけ**: Claude は「Models sold by Azure」ではなく Marketplace 経由のパートナーモデル。ただし「Hosted on Azure」形態が登場し opus-5-5(2026-09-22 追加)/ opus-5 / opus-4-8 / sonnet-5 / haiku-4-5 は Azure 基盤で GA(haiku-4-5 以外は Data Zone (US) 対応)まで来ており、「パートナーモデルはデータ所在が弱い」という従来の前提が変わっている。SDK は Azure OpenAI SDK ではなく **Anthropic SDK(AnthropicFoundry)+ Entra ID** という点が実装上の分岐点。2026-08-17 以降は Structured outputs / Web search / Web fetch / Tool search / MCP connector(Beta)も Hosted on Azure(US Data Zone 含む)で使え、「エージェント機能のために Anthropic 側ホスティングを選ぶ」必要はほぼ消えた。ただし両形態ともデータ処理者・SLA 提供者は Anthropic で、コンテンツ安全は Anthropic 側の安全システムのみ(Foundry 組み込みフィルターなし)。
- **serverless API deployments は実質レガシー**: classic 専用記事となり「Foundry resources への standard deployment を推奨」と明記。新規設計では選ばない。
- **ドキュメント間の齟齬**: 初版で指摘した Claude のライフサイクル表記の食い違いは schedule 2026-09-02 版で GA 表記に統一され解消。`gpt-realtime-2` の「schedule はリタイア済・sold は掲載継続」も schedule 2026-09-21 版でリタイア日が「—」になり解消。現在残る揺れは音声系(`gpt-4o-transcribe` 系・`tts-hd`: sold ページ Preview / schedule GA)、`gpt-oss-120b`(sold Preview / schedule GA)、`gpt-realtime-mini` の矛盾 2 行、GPT-6 Astra の EU Data Zone(2026-09-22 ブログは対応 / region-availability 表は US のみ)、Model router のリージョン数(ブログ 28 / 21・router ページ 32 / 23)、Grok 提供元表記(sold・how-to は SpaceXAI / schedule は xAI)。**2026-09 は schedule 自体が往復改訂した**(`gpt-4.1-nano` 2026-10-14 ⇔ 2027-04-14、`gpt-image-1.5` 2026-12-16 ⇔ 2027-06-16。いずれも 2026-09-21 版で初版記載の早い日付に戻った)ため、本番採用時は schedule の版日付と Models API の `deprecationDate` を併記して確認する。
- **GPT-6 系の EU Data Zone は Sol / Luna で可、Astra は要確認**: region-availability(2026-09-26 取得)では `gpt-6-sol` / `gpt-6-luna`(2026-09-22 GA)が Data Zone Standard の US・EU 両方に載る一方、`gpt-6-astra` は US Data Zone のみ(2026-09-22 ブログは Astra も EU Data Zone 対応と記載)。3 モデルとも Regional Standard・Batch はなし。EU データ境界が要件の案件では当面 Sol / Luna か gpt-5.6 系で設計し、Astra は表の更新を待って確認する。なお 2026-09-01 以降ローンチのモデルなので EU Data Zone は Global 比 +20% の新プレミアムが掛かる。当初の「Astra は tool calling に Responses API 必須・temperature 等非対応」は 2026-09-11 に撤廃済みで、Chat Completions 前提の既存アプリも移行しやすくなった。リタイア日は 3 モデルとも schedule 2026-09-21 版に未掲載。
- **ページ不在**: 新ドキュメント側の `/azure/foundry/concepts/fine-tuning-overview` は 404(FT 概要は `/azure/foundry/openai/how-to/fine-tuning` と classic 側に分散)。
