# 02. 詰まりどころ索引 — 症状から引く「原因・対処・出典」

[← ケースブック TOP](./README.md)

> **最終更新:** 2026-09-04(初版。公開記事の実在確認 2026-09-04)
> 機能・レイヤー別に「**症状 → 原因 → 設計上の対処 → 出典**」を索引化したもの。出典は **[公式]**(Microsoft Learn・公式ブログ・公式サンプル)/ **[実測]**(本リポジトリの labs、外部案件)/ **[記事]**(第三者の公開記事。サイト名と公開年月を併記)の 3 種([README の格付け](./README.md#出典の格付け-本セット固有のルール))。
> **読み方の注意:** [記事] は執筆時点の挙動であり、特に hosted agents は **2025-11 初回プレビュー → 2026-04 新基盤プレビュー → 2026-06〜07 GA** と短期間で基盤が入れ替わっている。**2026-04 以前の記事は旧基盤(`agent.yaml`・`az cognitiveservices agent`・`from_agent_framework()`)前提**で、現行では手順が変わっているものがある(該当行に「旧基盤」と明記)。ID(P-xx)は提案書・設計書から参照するためのもので、行の追加は末尾に足す(振り直さない)。

## 使い方

- **設計レビュー前:** 採用する構成のシナリオ([01](./01-scenario-playbook.md))が参照する P-ID を列挙し、「対処」欄が設計・見積もりに入っているかを確認する
- **提案書のリスク欄:** 症状と対処をそのまま転記できる粒度にしてある。出典 URL を添えると顧客説明の根拠になる
- **障害切り分け:** 症状の言葉(エラー文言)で検索する。「デプロイは成功するが実行だけ失敗」「読めるのに実行できない」「ポータルは見えるのに Playground が死ぬ」のような**誤診しやすい断面**を優先して収録した
