# docs/slides — SI チーム向け共有スライド

> **最終更新:** 2026-09-29 / **版:** 第 4 版(2026-09-29 時点の一次情報に同期+ビジュアル刷新。HTML / PDF 再生成済み)

課内 SI チーム向けの勉強会スライド(45 分想定+後日参照)。本リポジトリの調査資産(survey 4 セット+tech-selection-guide+labs)の**入口(1 層目)**として、「持ち帰る 3 つの判断能力」(決める順序 / 当たりの付け方 / 見積もりの現実)を軸に本編 38 枚+付録 9 枚へ再構成したもの。詳細は各スライド下部のリンクから survey の HTML(2 層目)へ降りる設計。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `foundry-si-overview.md` | スライド本体(Marp 形式)。**これが正**。スピーカーノートは HTML コメントで記載 |
| `themes/si-foundry.css` | カスタムテーマ。配色は `docs/survey/tools/md2html.py` の CSS 変数から移植(survey HTML と同一ブランド)。図解コンポーネント(カード / ゲート図 / 判断ツリー / タイムライン / 全幅アーキ図 / 要点列 / 旧→新対応 / 推奨構成マップ / ラボタイルなど)を定義 |
| `assets/icons/*.png` | カード用の Azure 公式アイコン(`diagrams` pip パッケージ同梱の Azure アーキテクチャアイコンを複製。アーキ図と同じ図柄) |
| `build.sh` | ビルド(HTML+PDF+リンク検証) |
| `tools/check_links.py` | MD 内の相対リンク・画像・`href`/`src` の存在チェック(標準ライブラリのみ) |
| `tools/sync_keys.py` | アーキ図スクリプトの「処理の流れ」(`steps_panel`)から、スライドの処理番号の説明(`<div class="keys" data-keys="<図名>">` のブロック)を自動生成する。新しい図のスライドには空の `<div class="keys" data-keys="<図名>"></div>` を 1 行置くだけでよい。**ブロック内は手で編集しない**(Marp は HTML コメントを発表者ノートにするため、マーカーはコメントでなく属性)。`--check` で同期確認。build.sh が毎回実行 |
| `tools/fonts.conf` | WSL に日本語フォントが無い環境向けに Windows 側フォントを参照する fontconfig |
| `foundry-si-overview.html` | 生成物(コミットする)。ブラウザで開くとスライド表示。`p` キーでプレゼンタービュー(ノート表示) |
| `foundry-si-overview.pdf` | 生成物(コミットする)。配布用。ノートは PDF 注釈として埋め込み |

## ビルド

```bash
bash docs/slides/build.sh              # HTML + PDF + リンク検証
SKIP_PDF=1 bash docs/slides/build.sh   # HTML のみ(執筆中の高速プレビュー)
```

- 前提: node / npx(marp-cli は npx で自動取得)。**PDF 変換は初回のみ** `npx -y puppeteer browsers install chrome-headless-shell@stable` で WSL 内にブラウザを導入(sudo 不要)
- WSL2(NAT モード)では Windows 側 Chrome をデバッグ接続できないため、WSL 内の chrome-headless-shell を使う。日本語フォントは `tools/fonts.conf` 経由で Windows 側フォント(Yu Gothic 等)を参照する
- **HTML / PDF は直接編集しない**(md2html.py と同じ原則。編集は Markdown 側で)

## 設計メモ

- **発表資料形式(3 段構成)**: 各スライドは「h1 = 項目タイトル(短い名詞句)→ `.msg` = スライドメッセージ(一文の主張)→ 図中心のボディ」で構成する。ボディは `.msg` と `.refs` の間で上下中央に配置される(テーマ側の flex + auto マージン。ボディを持つスライドには `.refs` を必ず置く)。本文の箇条書きは 2〜3 行まで、削った説明はスピーカーノートと 2 層目リンクへ
- **図と説明を一致させる**: 説明対象の数だけ図を出す。**アーキ図は 1 スライド 1 枚・全幅**(`.figfull`)で、`docs/survey/architecture/images/slide/*.png`(図スクリプトが出力するスライド用の切り出し版。タイトル・処理の流れパネル・注記帯を除いた本体)を使う。図中の処理番号 ①②③ の説明はスライド側の `.keys`(同じ青丸の番号)に HTML で書く — 図の中の小さい文字に頼らない。第 3 版の「図 2 枚並置(`.duo`)」は縮小で読めなくなるため廃止した(クラスは互換のため残置)
- **メッセージ行は 1 行に収める**: 図のスライドは縦の余白がない。`.msg` が 2 行に折り返すと下部の `.refs` がフッターと重なる(全角 38 字程度が上限)
- **背景はシンプルに**: 表紙も白地+左のアクセント帯。文字だけのスライドを作らない(カードにはアイコン、対応関係は `.vs`、選択肢は `.map` / `.qtree` など図解コンポーネントで)。表は全幅にして左寄りの偏りを作らない
- **略語は初出でスペルアウト**+付録 A7 に用語集。WAF は 2 義(Web Application Firewall / Well-Architected Framework)あるため本文では都度明記
- 図解コンポーネントの HTML ブロック内は Markdown が展開されない — 強調は `<b>`、リンクは `<a>` で書く(テーマ CSS のコメント参照)
- **出力を `html/` に分けず MD と同階層に置く**: Marp は md2html.py と違いリンクパスを書き換えないため、MD と出力の階層を揃えることで `../survey/architecture/html/*.html` という相対リンクが MD 編集時・HTML 閲覧時の両方で有効になる
- **リンクの二重化**: PDF を単体配布するとファイルリンクは切れるため、「詳細へ」導線はクリック可能リンク+可視のリポジトリパス表記のセットで書く
- **CJK 太字の罠**: `**...(HITL)**が` のように**全角約物の直後で太字を閉じて直後に文字が続く**と CommonMark の規則でパースされない。太字の境界は語の内側に置く(閉じ `**` の直前を文字にする)
- 図は `docs/survey/architecture/images/slide/*.png` を流用(図中テキストは日本語+サービス名は英語。再生成は `diagrams/*.py`。日本語フォントは Noto Sans CJK JP 等を自動検出 — `labs/maf-ports/tools/archdiagram.py`)
- 発表日はタイトルスライドと本 README の更新履歴に持たせ、ファイル名には入れない(改訂・再演に耐える)

## 更新方針

- survey の大型更新(Ignite 11 月・Build 5 月の直後)に合わせて内容を改訂する。特に**期限タイムライン(「重要期限」スライド・付録 A3)と GA/プレビュー状況(スライド 6)は陳腐化が速い**
- アーキ図を更新したら `diagrams/*.py` を再実行(スライド用 `images/slide/` も同時に出力される)→ スライドの要点列(処理番号の説明)が図の処理の流れと一致しているか確認
- PDF はビルドごとではなく**内容改訂時のみ再生成してコミット**(バイナリ差分の膨張を避ける)
