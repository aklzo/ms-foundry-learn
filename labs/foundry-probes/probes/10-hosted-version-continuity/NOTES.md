# Hosted agent の版更新と会話の継続 — 挙動発見メモ(2026-09-30 実測)

環境: japaneast / azure-ai-projects 2.7.0 / openai 3.20.0 / コンテナ protocol responses 2.0.0(コードデプロイ・`python_3_13`・Agent Server SDK `>=2.2.0,<3` を REMOTE_BUILD で解決)/ `idle_timeout_seconds=120` / App Insights 未接続 / 呼び出しはすべて同じ Entra ID(= 同じ利用者)。検証用エージェント([agent/main.py](./agent/main.py))はモデルを呼ばず、応答した版・セッション・受け取った履歴・`$HOME` のマーカー・コンテナの起動時刻を返す。

問い: **hosted agent の新しい版をデプロイした後も、旧版で始まった会話を続けられるか。**

## 結果

会話のつなぎ方は 3 通り。P = `previous_response_id` だけ(Port 15 の中間層と同じ)/ S = `previous_response_id` + `agent_session_id` / C = `conversation` ID。「履歴」はエージェントが受け取った過去の item 数(user と assistant で 1 往復 2 件)。

| # | 操作 | P | S | C | 新しい会話 N |
| --- | --- | --- | --- | --- | --- |
| 1 | v1 で開始(2 ターン) | v1・履歴 2 | v1・履歴 2 | v1・履歴 2 | — |
| 2 | 100% を v2 へ(直後。セッションは起動中) | **v1 のまま**・履歴 4・`$HOME` 保持 | 同左 | 同左 | v2 で開始 |
| 2b | v2 に明示固定した新しいセッションを渡す | — | **v2**・履歴 6(全部)・`$HOME` なし | **v2**・履歴 6・`$HOME` なし | — |
| 3 | 100% を v1 へ戻す(直後) | — | — | — | **v2 のまま**・履歴 2 |
| 4 | v1 の版を削除 | 409 → `force=true` で削除 → **v2**・履歴 6・v1 時代の `$HOME` 保持・同じセッション ID | 同左 | 同左(履歴 8) | — |
| 5 | 休止(120 秒超)後、100% を v3 へ → 再開 | **v3**・履歴 10・`$HOME` 保持・同じセッション ID・コンテナは新規起動 | v2 に**明示固定**したセッション → **v3**・履歴 8 | 同左(履歴 10) | 暗黙のセッション → **v3**・履歴 6 |

5 は当日 3 回に分けて実行した(1 回目は v3 のデプロイが 41 秒で終わり、P はまだ休止前だったため v2 のまま応答した)。probe.py では 1 本にまとめてある。

## 発見(挙動)

1. **同じエージェントの中なら、会話は版をまたいで続けられる。**履歴はエージェント+利用者の単位で保存され、どの版からも読める。旧版を削除しても消えない。一方、**別のエージェント**の response ID は 404(Port 15 の実測)で、会話はエージェント単位に分かれる。
2. **どの版が応答するかは、そのセッションのコンテナが起動しているかで決まる。**
   - 起動中(最後のアクセスから idle_timeout 以内)は、ルーティングを変えても**旧版のコンテナが応答し続ける**(#2・#3)
   - 休止した後の次のターンは、**その時点のルーティング先の版で再開する**(#5)。セッション ID・履歴・`$HOME` のファイルは引き継ぐ。セッションの `version_indicator` も新しい版に書き換わる
   - → 既定の idle_timeout(15 分)なら、**会話が 15 分途切れた時点で新版に切り替わる**。話し続けている会話は旧版のまま
3. **ロールバックも同じ規則。**戻した直後、新版で起動中の会話は新版のまま(#3)。話し続けている会話には効かない。
4. **旧版の削除は、結び付いたセッションが残っていると 409 conflict**(`Version has 3 deletion-blocking session(s), including active or non-expired idle sessions. Retry after the sessions expire, or use force=true to cascade-delete them.`)。セッションの有効期限は **30 日**(`expires_at − created_at` = 2,592,000 秒)で、休止中のセッションも期限までは削除を妨げる。
5. **`force=true` で旧版を削除すると、次のターンで同じセッション ID のまま現行版に作り直され、履歴も `$HOME` のファイルも残った**(#4)。「cascade-delete」という文言から想像される会話の消失は起きなかった。
6. **明示的な移行もできる。**`create_session(version_indicator=VersionRefIndicator(agent_version=新版))` で作ったセッションの ID を `agent_session_id` に渡すと、`previous_response_id` / `conversation` のどちらでも、起動中の旧版を離れて新版で履歴全体を引き継げる(#2b)。`$HOME` のファイルは引き継がない(新しいサンドボックスのため)。
7. **App Insights 未接続では `APPLICATIONINSIGHTS_CONNECTION_STRING` は注入されない**(全ターンで `false`)。architecture 09 §3.6 の案 3「接続しない」の前提を確認できた。
8. 応答の `model_extra` に `agent_session_id` と `agent_reference`(`{"name", "version"}`)が入る。v3 で応答したターンでは `version: "3"`(旧版で応答したターンの値は記録していない)。

## 公式ドキュメントとの食い違い([manage-hosted-sessions](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/manage-hosted-sessions) ms.date 2026-08-21)

| 公式の記述 | 実測 |
| --- | --- |
| 「`agent_session_id` を付けない呼び出しは新しいサンドボックスに入る」「呼び出しは `previous_response_id` だけからセッションを推定しない」 | **`previous_response_id` だけでも前の応答のセッションに戻った**(P の全ターンで同じセッション ID・`$HOME` 保持) |
| 「`version_indicator` で版に固定すると、新しい版を公開しても以降のターンはその版を使い続ける」 | **v2 に明示固定したセッションも、休止明けは v3 で再開した**(#5)。固定が効いたのは起動中だけ |

どちらも 1 回の実測(1 リージョン・1 日)。仕様の変更や不具合の修正で変わる可能性があるので、これに依存する設計では再実測を受入条件に入れる。

## つまりどころ

- **「ルーティングを切り替えたのに旧版が応答する」**: 起動中のセッションは旧版のまま。新版の確認は**新しい会話**で行う(既存の会話で確かめると、idle_timeout 以内は旧版の結果を見て誤判定する)
- **「旧版を削除できない(409)」**: 休止中のセッションも期限(30 日)までは削除を妨げる。すぐ消すなら `force=true`
- **新版は、旧版が書いた履歴と `$HOME` を読む**: 休止明けは新版で再開するので、ツール呼び出しの形式・会話の前提・`$HOME` のファイル形式を変える版では後方互換を持たせる(LangGraph の backward-compatibility ガイドと同じ考え方)

## SI 判断メモ

- 「エージェントを更新すると過去の会話を続けられない」は、Foundry hosted agent には当てはまらない。運用上の論点はむしろ、**切り替わる時点が会話ごとにばらつく**こと(起動中は旧版、休止明けに新版)。
- リリース手順の型:
  - **通常の改修**: ルーティングを切り替えるだけ。話し続けている会話も、idle_timeout(既定 15 分)の間が空けば新版に移る
  - **すべての会話をすぐ新版へ移したい修正**(権限・業務ルールの不具合など): 旧版を `force=true` で削除する(実測では履歴もファイルも残った)。または中間層で、新版に固定したセッションを作って渡す
  - **ロールバック**: 起動中の会話には効かない。問題の版にいる会話をすぐ止めるなら、その版を `force=true` で削除する
- **セッションは会話と別物で、休止しても別のセッションにはならない。**同じセッション ID(最長 30 日)のままコンテナだけが止まり、次の発言で起動し直すときに現行の版が選ばれる。旧版が残るのは「やり取りが続いている会話」だけ(例: idle_timeout 15 分・10:10 に修正版へ切り替え → 5 分おきに話し続けている利用者は 15 分以上の間が空くまで旧版、30 分ぶりに戻った利用者は新版)
- **コードを直しても、会話履歴に残った誤りは消えない。**旧版の誤った回答・ツール結果を新版が文脈として読む。影響の大きいバグでは新しい会話を始めてもらうか、新版側で旧版の出力を含む会話を検知する
- **「休止明けに新版へ移る」は公式の記述と食い違う挙動**(上の表)。文書どおりに変わると旧版が最長 30 日使われうるので、自動の切り替えに頼らず、必ず移したい修正と緊急のロールバックでは問題の版を `force=true` で削除する手順を明記し、版更新のたびに再確認する
- 受入試験に「更新前に始めた会話の続き」「ロールバック後の続き」「旧版を削除した後の続き」を入れる。判断基準は [architecture 09 §6.3](../../../../docs/survey/architecture/09-operations.md#63-エージェントのバージョニングとリリース)。
