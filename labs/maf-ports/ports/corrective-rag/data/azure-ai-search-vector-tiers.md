# Azure AI Search: ベクトル検索と料金レベル(ラボ用要約)

> このファイルは corrective-rag ポートのサンプルコーパス。Microsoft Learn の
> Azure AI Search ドキュメントを学習用に要約したもの(2026-07 作成、ラボ内利用)。

## ベクトル検索の基本

Azure AI Search のベクトル検索は、インデックスのフィールドに
`Collection(Edm.Single)` 型のベクトルフィールドを定義し、次元数
(`vectorSearchDimensions`)とベクトル検索プロファイルを指定して使う。
近似最近傍(ANN)アルゴリズムは HNSW(Hierarchical Navigable Small World)が
既定で、網羅的 KNN(exhaustiveKnn)も選択できる。距離指標はコサイン、
ドット積、ユークリッドから選ぶ。OpenAI の text-embedding-3-small(1536 次元)
や text-embedding-3-large(3072 次元)の埋め込みがよく使われる。

クエリは 2 通りある。クライアント側で質問文を埋め込みベクトルに変換して
`VectorizedQuery` として送る方法と、インデックス側にベクトライザ(Azure
OpenAI 接続)を構成してテキストのまま送る **integrated vectorization**
(`VectorizableTextQuery`)である。integrated vectorization はインデクサ+
スキルセットによる取り込み時の自動チャンク・自動埋め込みにも対応する。

キーワード検索(BM25)とベクトル検索を同時に実行して融合(RRF: Reciprocal
Rank Fusion)する**ハイブリッド検索**も、search_text とベクトルクエリを
併記するだけで実行できる。

## 料金レベル(SKU)の要点

- **Free**: 評価・学習用。**インデックス 3 個まで、ストレージ 50 MB**、
  パーティション/レプリカの拡張不可、SLA なし。**セマンティックランカーは
  使えない**。ベクトル検索自体は Free でも動作する。
- **Basic**: 小規模な本番向けの最安有償レベル。インデックス 15 個、
  ストレージは数十 GB 規模(リージョン・作成時期で異なる)、レプリカ 3 まで。
  **セマンティックランカー(意味的リランキング)が有効化できる**。
- **Standard S1〜S3**: パーティション・レプリカを拡張できる本番向けレベル。
  高いクエリ負荷・大規模インデックスに対応する。

セマンティックランカーは BM25/ハイブリッドの上位結果を言語理解モデルで
リランキングする機能で、Basic 以上のレベルで有効化し、利用量に応じて課金
される。RAG の検索品質を上げる代表的な手段だが、Free レベルでは試せない。

## RAG での利用

RAG のリトリーバとしては、チャンク化した文書をベクトルフィールド付きで
インデックスに投入し、質問の埋め込みで上位 k 件(既定 50、RAG では 3〜10 が
一般的)を取得する。取得結果の `@search.score` は距離指標に基づくスコアで、
ハイブリッド検索では RRF スコアになる。
